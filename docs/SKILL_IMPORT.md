# Імпорт здібностей

В адмін-панелі «Навички» відкрийте «Імпорт здібностей». Завантажте JSON
(рекомендовано), CSV UTF-8 з комами або структурований DOCX. Максимум 1 MB,
500 записів. Шаблони всіх трьох форматів доступні на сторінці.
Приклад із Base та рівнем 0: [skills-import.json](../examples/skills-import.json).

Оберіть режим: додати нові, оновити наявні або додати та оновити. Перегляньте
таблицю, зауваження та лічильники. Зніміть позначки із зайвих записів. Помилкові
рядки заблоковані. Для ручного виправлення відкрийте редактор JSON і натисніть
«Перевірити виправлення». Лише окреме натискання «Підтвердити імпорт» записує дані.
Звіт містить кількість записів і посилання на резервну копію до імпорту.

## Модель та ключі

Використовуються SkillCategory → SkillSubclass → SkillBranch → SkillDefinition.
`class`, `subclass` — точні назви. `branch` — чинний індекс гілки **від 0**:
звичайно 0–2, для спеціального підкласу — 0–1 згідно з max_branches_for_subclass.
При відсутності гілок створюється індекс 0; при єдиній наявній — використовується
вона. Якщо гілок кілька, потрібно вказати індекс явно. Ключ: клас + підклас +
гілка + рівень. Назва здібності сама по собі ніколи не є ключем. Неоднозначні
назви класів/підкласів/індекси блокуються. Експорт також містить стабільний `id`;
він має відповідати ключу. Перенесення між гілками через імпорт не підтримується.

`level`: Base/BR або 0–7. `name`: до 120 символів. `ability_type`: Active/Passive
або Активна/Пасивна. `distance_type`: SELF/INT_METERS або На себе/На ціль.
`distance_int` потрібен для INT_METERS. `cost_int`, `distance_int`,
`cast_time_seconds`, `duration_seconds`: цілі невід’ємні числа до 9999 або null.
`description`, `components`: звичайний текст до 9999 символів.
`is_enabled`: true/false. `requirements`: список текстів (або об’єктів
req_type/req_value для збереження чинних типів при експорті/відновленні).

Обов’язкові поля: клас, підклас, рівень, назва. Пропущені опис/компоненти порожні,
тип за замовчуванням Passive, дистанція SELF, is_enabled=true. Оновлення — повний
запис, не PATCH: перед редагуванням експортуйте чинні дані, щоб не очистити
непередані необов’язкові поля. Оновлення зберігає ID та ProfileSkillState.

Механічні ефекти не мають окремої моделі; непорожнє поле effects блокує імпорт.
Перенесіть потрібне пояснення в опис вручну. Текстові залежності зберігаються як
SkillRequirement; імпорт не вигадує виконувану механіку. Для активації рівня 0
потрібен активний Base, наступні рівні потребують усіх попередніх — чинні правила
skills_toggle залишаються незмінними. Нові здібності видно у звичайному каталозі.

## DOCX

Підтримуються українські поля з прикладу завдання, формат «Поле: значення»,
кілька здібностей, багаторядковий опис. Контекст Клас/Підклас діє до наступної
зміни. Стилі Heading1/Heading2/Heading3 без двокрапки позначають клас/підклас/назву.
Нерозмічений текст поза описом відхиляється. Довільні таблиці, зображення, старий
DOC та автоматичне семантичне тлумачення не підтримуються. Компоненти — текст.
Залежності в CSV/DOCX задаються JSON-масивом. DOCX не виконує макроси, не витягає
файли на диск і не завантажує зовнішні ресурси; максимум 200 ZIP-елементів,
4 MB сумарного розпакування, заборонені DTD/entities, шифрування та VBA.

## Цілісність і відновлення

Сервер перевіряє адміністративні права, CSRF та підписаний перегляд (30 хвилин).
Змінений файл, режим чи каталог вимагають нового перегляду. SQLite confirmation
отримує write lock до повторної перевірки; запис усіх обраних рядків атомарний.
Помилка БД відкочує імпорт. Імпортовані рядки відображаються текстом; чинний
адмін-редактор також екранує HTML перед побудовою форми.

Перед записом повний JSON зберігається в instance/skill_import_backups, поза
публічними static/uploads. Копії доступні лише адміністраторам. Завантажте копію
зі звіту та зберігайте її разом зі звичайними резервними копіями БД. Для відкату
оновлень завантажте JSON у режимі «Оновити наявні», перегляньте та підтвердьте.
Якщо копія перевищує 1 MB/500 рядків, розділіть її на менші JSON-масиви. Нові
записи та подальші зміни інших адміністраторів автоматично не видаляються;
перевіряйте записи при відновленні. Наявні JSON-копії не видаляються автоматично:
адміністратор обслуговує строки зберігання каталогу резервних копій.

Експорт усіх здібностей, класу чи підкласу доступний на сторінці. Імпорт не додає
міграцій або сервісів і не потребує нових production-залежностей. Після
розгортання перезавантажте WSGI та статичні файли; каталог instance має бути
доступний для запису. Тестування виконуйте лише з DRA_DATA_DIR у /tmp:
`DRA_DATA_DIR=/tmp/dra-import-tests .venv/bin/pytest -q`.
